# ML-извлечение из нормативов: решение, сравнение подходов, обоснование

Это документ-обоснование: **что из ML-подхода используется, что отложено и на каких
числах это решено**. Хронология шагов и карта ноутбуков — в `README.md`; рабочий стек —
в `PIPELINE.md`; проверка — в `VERIFY.md`.

> **Статус (обновлено 2026-10-04).** Действующее решение — **вариант A2:
> детерминированная реконструкция LaTeX из текстового слоя PDF** (`text_layer_latex.py`),
> без OCR и нейросетей. `pix2text`/`DocLayout-YOLO` остаются только для сканов. MinerU
> изучена и как пайплайн отклонена (`README.md` §3). Ранние разделы ниже сохранены как
> история решения, а не как текущий план.

## 1. Действующее решение (A2)

Для текстовых PDF LaTeX формул собирается из **текстового слоя**: `pdfplumber` отдаёт
символы с геометрией (`size`, `top`), скрипты восстанавливают `_{...}`/`^{...}`,
математические начертания приводятся через NFKC, глифы Adobe Symbol (PUA) — таблицей
кодировки шрифта, а кириллица транслитерируется в латиницу **только для `sympy`**
(отображение остаётся кириллическим).

Почему A2, а не OCR:

- **Точность кириллицы.** Текстовый слой хранит `h_{зар}`, `λ_с`, `P_{раб}` корректно;
  OCR-модели, обученные на латинице, читают их как `h_{3arrom}`, `\lambda_c`,
  `P_{pa6}`. Для русских нормативов это решающий аргумент.
- **Детерминированность и отсутствие моделей.** Нет GPU, нет весов, нет нестабильности
  между прогонами — совпадает с правилом «никаких LLM/нейросетей в расчётном пути».
- **Скорость.** Секунды на документ против ≈31 с на формульную страницу у MinerU.

Показатели (полный обзор, 2026-10-04): СП 31 — 13 формул, `sympy` 13/13, структурно
13/13; СП 22 — 127 формул, `sympy` 93, структурно 121. На момент первого замера в `nb06`
A2 давал 9/13 на СП 31; дальнейшие фиксы каскада (`nb08` §11) и обзора подняли до 13/13.

## 2. История: почему пришли именно к A2

Кратко (подробно — `README.md` §1):

1. `nb01`: regex для таблиц не обобщается; на text-based `pdfplumber.find_tables` точнее ML.
2. `nb02`: end-to-end Nougat на русском не работает — выбран слоистый подход.
3. `nb03`: pix2text читает формулы визуально верно, но `latex2sympy2` парсит лишь 14%.
4. `nb04`: rubert-tiny2 — masked LM, не NER; NER отложен.
5. `nb05`: собран конвейер и исправлены коллизии `id` кириллица↔латиница.
6. `nb06`: **поворот** — кириллица корректна в текстовом слое; родился A2.
7. `nb07`: CNN-фильтр шума — research, в основной путь не обязателен.
8. `nb08`: системы, 11 фиксов, sympy-каскад, условия/легенды; текущий рабочий модуль.
9. `nb09`: MinerU изучена и отклонена как пайплайн (кириллица + скорость).
10. `nb10`: ключ формулы — `(пункт, номер)` геометрически, а не номер.

## 3. Сравнение подходов (задача → вердикт)

Таблица сохранена из первоначального исследования (`nb01`–`nb06`) — это обоснование,
почему от каждого ML-варианта отказались или отложили.

| Задача | Модель/метод | Вердикт | Почему |
|---|---|---|---|
| Layout (блоки таблиц/формул/подписей) | DocLayout-YOLO | **Только сканы** | на text-based проигрывает regex+геометрии; нужен растр |
| Структура таблицы | `pdfplumber.find_tables` | **Основной** | на text-based извлекает сетку и ячейки корректно, не зависит от языка |
| Структура таблицы | TableTransformer | **Только сканы/сложное** | на пилоте хуже pdfplumber (3 строки вместо 5, header не отделён) |
| End-to-end страница → Markdown | Nougat-base | **Отклонён** | на русском пусто/мусор без дорогого fine-tune |
| Формулы → LaTeX (текстовые PDF) | `text_layer_latex` (A2) | **Основной** | детерминированно, точная кириллица, без моделей |
| Формулы → LaTeX (сканы) | pix2text (LatexOCR) | **Отложен** | читает визуально, но парсинг низкий; кириллицу ломает |
| Формулы → LaTeX | texify | **Отклонён** | несовместим со стеком (transformers + pdfplumber) |
| NER обозначений/единиц | rubert-tiny2 (fine-tune) | **Отложен** | нет NER-головы и размеченного корпуса; закрыт regex+словарём |
| Нормализация обозначений | rubert-tiny2 embeddings | **Опционально** | группирует варианты написания (`γII`≈`гамма_II`, 0.85) |

**Главный вывод.** End-to-end «одна модель вместо пайплайна» на русских нормативах не
работает без дорогого fine-tune. Побеждает **слоистый детерминированный подход**, а для
кириллицы — **текстовый слой PDF как источник правды** (A2).

## 4. Метрики, на которых основано решение

| Эксперимент | Метрика | Значение |
|---|---|---|
| DocLayout-YOLO, пилотные стр. 015/028/038/054 | находит `table`/`table_caption`/`isolate_formula` | 4/4 страниц |
| TableTransformer на таблице 4.1 (стр. 15) | сетка | 3 строки × 5 колонок (header не отделён) |
| regex `extract_tables` на той же таблице | строк | 5 (полнее, но со spanning-дублями) |
| Nougat-base на русских стр. 15/28/38 | осмысленный вывод | 0/3 |
| Nougat-base на англ. синтетике | вывод | корректный |
| pix2text на формулах стр. 1–60 | распознано | 35/35 |
| pix2text → `latex2sympy2` | парсится | 5/35 (14%) |
| `correct_latex` v2, СП 31 | парсится | 10/21 (48%) |
| **A2 (`text_layer_latex`), СП 31, первый замер** | парсится | **9/13 (69%)**, все с кириллическими индексами |
| **A2 + каскад `nb08` §11, СП 31, обзор 2026-10-04** | парсится | **13/13** |
| rubert-tiny2 embeddings | `γII` vs `гамма_II` | cosine 0.85 |

Остаточные отказы `latex2sympy2` — **не про алфавит**: суммы с пределами над/под `Σ`,
химия `Fe^{2+}`, `\pm`, слитные буквы (`dlb`), голый `E`, сложные вложенные индексы.

## 5. Следующие шаги (приоритеты)

### P0 — порт A2 в прод (замена pix2text для текстовых PDF)

- Вынести `text_layer_latex.py` в `normatives_pipeline` как детерминированный шаг
  `latex = f(text_layer)`; `pix2text` оставить только для сканов с явным статусом.
- Расширить `parser.toml [parser.pua_map]` до полной таблицы Adobe Symbol.
- Владелец — Egor (data-zone). Критерий приёмки: ≥ 90% формул парсятся на корпусе
  текстовых СП, без хардкода под документ.

### P1 — layout как fallback для сканов

DocLayout-YOLO остаётся для страниц без текстового слоя; на text-based regex+геометрия.

### P2 — TableTransformer только для сканов/сложного spanning

Перед внедрением: корректный bbox, header vs data, spanning, склейка таблиц через страницы.

### P3 — отложено (не в MVP)

Nougat fine-tune, полноценный NER, texify, OCR сканов. Стратегически — **вариант C**
(см. §6).

## 6. Развитие (вариант C): fine-tune кириллического LaTeX-OCR

Стратегическое решение на случай сканов и сложной вёрстки: дообучить распознаватель
`изображение → LaTeX` на синтетических парах с `\text{кириллица}` (рендер
`h_{\text{зар}} = h_{\text{расч}} + 0{,}3` и т.п.), аугментация шрифтов/масштаба.

Условия: validation-датасет реальных формул с эталонным LaTeX; совместимый стек texify
(transformers<4.40) или продолжение на pix2text. **Когда браться:** после A2/B и готового
датасета. Не блокер MVP.

## 7. Что нужно для честного развития

Сейчас метрики — на пилоте. Для оценки P1/P2 и варианта C нужен validation-датасет:
10–20 таблиц с эталонной разметкой, 30–50 формул с эталонным LaTeX, 2–3 разных документа.

## 8. Итог для команды

1. **Сейчас:** A2 — текстовый слой вместо pix2text для текстовых PDF; обзор формул
   (`verify_corpus.py`) и HTML `human-views/`.
2. **Дальше:** порт A2 в прод (P0); layout/TableTransformer — только сканы (P1/P2).
3. **Развитие:** fine-tune LaTeX-OCR (C) — после A2 и датасета. **Не делаем:** Nougat,
   texify, полноценный NER, MinerU как пайплайн.

Артефакты: ноутбуки `nb01`–`nb10` (код, метрики, выводы); модуль `text_layer_latex.py`;
обзор `verify_corpus.py`; HTML `human-views/`.
