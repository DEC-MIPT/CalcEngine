# Детерминированный пайплайн нормативов: стек, результаты, что дальше

Документ фиксирует, какие технологии выбраны в `normatives_pipeline`, почему именно они и
чего удалось добиться. Точка входа и история решения — `README.md`; обоснование ML-выбора —
`RECOMMENDATION.md`; проверка — `VERIFY.md`.

## 1. Принцип

Расчётный и нормативный путь — **детерминированный**: никаких LLM/нейросетей в извлечении
структуры, поиске и чтении. Нейросетевые модели (`DocLayout-YOLO` + `pix2text`) допускаются
только как **отдельный, отложенный** OCR-шаг для формул на **сканах** (PDF без текстового
слоя); он не участвует в контракте с backend и не влияет на результат по умолчанию.

**Текстовый слой PDF — источник правды для формул и кириллицы.** Для PDF с текстовым слоем
LaTeX формул собирается из геометрии `pdfplumber` (детерминированно, без моделей), поэтому
проблема «OCR путает кириллицу» (`h_{зар}`→`h_{3arrom}`) в основном пути отсутствует.

## 2. Стек и обоснование

| Слой | Технология | Почему выбрана | Что отклонено |
|---|---|---|---|
| Текстовый слой | `pdftotext -layout` (poppler) | быстрый, стабильный, сохраняет кириллицу и порядок строк | Nougat — на русском пусто/мусор без fine-tune |
| Таблицы | `pdfplumber.find_tables` | на text-based даёт корректную сетку и ячейки; не зависит от языка | TableTransformer — только для сканов/сложных (хуже на текстовых) |
| Пункты/формулы (детекция) | regex по конфигу (`parser.toml`) | прозрачно, настраивается без кода; покрывает нумерованные и синтетические формулы | ML-детекция блоков — отложена (fallback для сканов) |
| Формулы → LaTeX (**текстовые PDF**) | `text_layer_latex` (геометрия `pdfplumber` + NFKC + таблица Symbol) | детерминированно, точная кириллица, без OCR и словаря; **вариант A2** | `pix2text` — кириллицу ломает, парсинг ниже |
| Формулы → LaTeX (**сканы**) | `pix2text` + `correct_latex` + `notation_restore` (опц. extras) | OCR для PDF без текстового слоя; парсинг поднят 19%→48% на СП 31 | `texify` (несовместим со стеком), Nougat, MinerU |
| Поиск | `pymorphy3` (лемматизация) + Postgres `pg_trgm` | без внешних сервисов и эмбеддингов; recall@k для MVP достаточен | `rubert-tiny2` embeddings — опционально, вне расчётного пути |
| Хранилище | PostgreSQL, `psycopg2`, `execute_values` | транзакции, GIN-индексы, батч-вставка; единая БД каталога | — |
| Скриншоты для ревью | PyMuPDF (`pymupdf`) по bbox из pdfplumber | быстрый растр точной области, без внешних сервисов | — |
| Контракт вывода | `configs/parser.toml` `[output]` | форма payload задаётся конфигом, а не кодом; backend читает те же ключи | — |

**Про MinerU.** Оригинальная MinerU (`nb09`) как пайплайн **отклонена**: OCR-головки ломают
кириллицу, CLI перезагружает модели на каждый вызов (≈31 с/формульная страница). Отдельные
идеи (номер формулы как сущность `\tag{}`, единое «middle»-представление блоков, разделение
стадий) учтены, но зависимости нет. Детали — `README.md` §3.

## 3. Что удалось добиться

### 3.1 Сквозной цикл PDF → БД → чтение (см. `VERIFY.md`)

На **всех текстовых СП** репозитория:

| Документ | Пункты | Формулы | Таблицы | Ячейки | roundtrip (экстрактор=БД) | Независимая таблица | NormRef |
|---|---|---|---|---|---|---|---|
| СП 22.13330.2016 | 647 | 130 | 121 | 2959 | 2959 = 2959 | табл. 5.8: 146 = 146 | 0 нарушений |
| СП 24.13330.2021 | 292 | 91 | 33 | 1869 | 1869 = 1869 | табл. 7.2: 98 = 98 | 0 |
| СП 30.13330.2020 | 393 | 46 | 75 | 2909 | 2909 = 2909 | табл. 5.1: 200 = 200 | 0 |
| СП 31.13330.2021 | 725 | 18 | 84 | 2176 | 2176 = 2176 | табл. 30: 121 = 121 | 0 |
| СП 45.13330.2017 | 818 | 23 | 77 | 945 | 945 = 945 | табл. 12.2: 8 = 8 | 0 |

- PDF → парсинг → БД → чтение: **без потерь и порчи** на всех проверенных СП.
- Обозначение и год издания берутся с титульной страницы (не из имени файла).
- Payload формулы = ровно `[output] formula_keys`; `NormRef` пятиполевой, без пустых `document`.
- Тесты: `88 passed` (корпусные проверки по всем 5 СП выполняются, не скипаются).

### 3.2 Формулы: полный обзор (обновлено 2026-10-04)

`research/verify_corpus.py` проходит все страницы, реконструирует LaTeX текстовым слоем и
считает структурные дефекты и разбор `latex2sympy2` каскадом (со сбросом глобального `var`,
`nb08` §10.2/§11). HTML-обзор «PDF ↔ LaTeX» — `research/human-views/`.

| Документ | Формул | sympy ok | Структурно ok | Кириллица в базе |
|---|---|---|---|---|
| СП 31.13330.2021 | 13 | 13/13 | 13/13 | 4 |
| СП 22.13330.2016 | 127 | 93 | 121 | 16 |

- Ключ идентичности формулы — **`(пункт, номер)` геометрически**, не номер: номер может
  повторяться (п. 9.88 и 9.145 в СП 31) и терять формулы (`nb10`).
- Визуальная сверка PDF ↔ БД подтверждена для пилота (формула 5.7, таблица 5.5) и СП 31
  (формула 9); генератор — `research.make_review_html`, обзор — `research/verify_corpus.py`.

## 4. Над чем ещё стоит поработать

1. **Порт A2 в прод.** Сейчас реконструкция LaTeX из текстового слоя живёт в
   `research/text_layer_latex.py`. Нужно вынести её в `normatives_pipeline` как
   детерминированный шаг, а `pix2text` оставить только для сканов с явным статусом.
   Расширить `parser.toml [parser.pua_map]` до полной таблицы Adobe Symbol.
2. **Заголовки таблиц (WP9, задача 2.4).** Значения таблицы хранятся, но привязка
   «строка → символ+единица» и выбор строки по заголовку — отдельная задача каталога.
3. **Коэффициенты: edition/clause.** Для табличных коэффициентов `edition` сейчас
   `unverified` (инвариант допускает). После сверки с первоисточником (WP9, 2.5) — конкретны.
4. **Таблицы с одним номером на одной странице.** БД не хранит идентификатор pdf-таблицы;
   независимая сверка неоднозначна при повторе номера (roundtrip точен). Решение — хранить
   `table_index`/bbox.
5. **Кириллица в формулах — закрыто решением (2026-10-04).** `pix2text` путает кириллицу,
   но текстовый слой хранит её корректно; `research/text_layer_latex.py` собирает LaTeX из
   геометрии `pdfplumber`, NFKC для начертаний, таблица Symbol для PUA; кириллица
   транслитерируется только для `sympy`. Обзор: СП 31 — 13/13 sympy. Остаётся порт в прод
   (п. 1). Отклонённые варианты B (гибрид OCR) и C (fine-tune) — для сканов
   (`RECOMMENDATION.md` §6).
6. **Коллектор зависит от сети** (`api.faufcc.ru`). Офлайн-цикл работает на уже скачанных
   PDF; стоит добавить проверку целостности/версий.
7. **Дедупликация формул.** На СП 22 из 133 детекций в БД 130 — логировать, какие три
   отброшены (сейчас молча).
8. **Покрытие кода.** Держать ≥ 95% branch coverage; проверять `pytest` с
   `DEC_DATABASE_URL` (иначе DB-тесты скипаются).
9. **Коллизии `id` кириллица↔латиница — исправлено (2026-10-04).** `parser/symbols.py`
   добавляет суффикс `_cyr` и сохраняет регистр (`А`→`A_cyr`, `а`→`a_cyr`, `\text{с}`→`s_cyr`;
   латинское `s`→`s`). Коллизий 0 (было 8 групп по извлечению / 11 с manifest); тесты
   `tests/test_symbols.py`, `tests/test_cyrillic.py`, эксперимент `nb05`; аудит/миграция —
   `python -m normatives_pipeline.parser.cyrillic [--apply]`. Остаётся нормализация формата
   `_g` vs `_{g}` (не про алфавит).
