# Детерминированный пайплайн нормативов: стек, результаты, что дальше

Документ фиксирует, какие технологии выбраны в `normatives_pipeline`, почему именно они и
чего удалось добиться. Дополняет `RECOMMENDATION.md` (там — сравнение ML-подходов и
обоснование, почему end-to-end нейросети отложены). Проверка цикла описана в `VERIFY.md`.

## 1. Принцип

Расчётный и нормативный путь — **детерминированный**: никаких LLM/нейросетей в извлечении
структуры, поиске и чтении. Нейросетевые модели (DocLayout-YOLO + pix2text) допускаются
только как **отдельный, отложенный** шаг распознавания LaTeX для формул без manifest; он не
участвует в контракте с backend и не влияет на результат по умолчанию.

## 2. Стек и обоснование

| Слой | Технология | Почему выбрана | Что отклонено |
|---|---|---|---|
| Текстовый слой | `pdftotext -layout` (poppler) | быстрый, стабильный, сохраняет кириллицу и порядок строк | Nougat — на русском пусто/мусор без fine-tune |
| Таблицы | `pdfplumber.find_tables` | на text-based PDF даёт корректную сетку и ячейки; не зависит от языка | TableTransformer — только для сканов/сложных (хуже на текстовых) |
| Пункты/формулы (детекция) | regex по конфигу (`parser.toml`) | прозрачно, настраивается без кода; покрывает нумерованные и синтетические формулы | ML-детекция блоков — отложена в основной путь |
| Поиск | `pymorphy3` (лемматизация) + Postgres `pg_trgm` | без внешних сервисов и эмбеддингов; recall@k для MVP достаточен | `rubert-tiny2` embeddings — опционально, вне расчетного пути |
| Хранилище | PostgreSQL, `psycopg2`, `execute_values` | транзакции, GIN-индексы, батч-вставка; единая БД каталога | — |
| Формулы → LaTeX | `pix2text` + `correct_latex` + `notation_restore` (опц. extras) | распознаёт формулы; парсинг поднят с 19% до 48% на СП 31 | `texify` (несовместим со стеком), Nougat |
| Скриншоты для ревью | PyMuPDF (`pymupdf`) по bbox из pdfplumber | быстрый растр точной области, без внешних сервисов | — |
| Контракт вывода | `configs/parser.toml` `[output]` | форма payload задаётся конфигом, а не кодом; backend читает те же ключи | — |

## 3. Что удалось добиться

Сквозная проверка (см. `VERIFY.md`) на **всех текстовых СП** репозитория:

| Документ | Пункты | Формулы | Таблицы | Ячейки | roundtrip (экстрактор=БД) | Независимая таблица | NormRef |
|---|---|---|---|---|---|---|---|
| СП 22.13330.2016 | 647 | 130 | 121 | 2959 | 2959 = 2959 | табл. 5.8: 146 = 146 | 0 нарушений |
| СП 24.13330.2021 | 292 | 91 | 33 | 1869 | 1869 = 1869 | табл. 7.2: 98 = 98 | 0 |
| СП 30.13330.2020 | 393 | 46 | 75 | 2909 | 2909 = 2909 | табл. 5.1: 200 = 200 | 0 |
| СП 31.13330.2021 | 725 | 18 | 84 | 2176 | 2176 = 2176 | табл. 30: 121 = 121 | 0 |
| СП 45.13330.2017 | 818 | 23 | 77 | 945 | 945 = 945 | табл. 12.2: 8 = 8 | 0 |

- PDF → парсинг → БД → чтение: **без потерь и порчи** на всех проверенных СП.
- Обозначение и год издания берутся с титульной страницы (не из имени файла).
- Payload формулы = ровно `[output] formula_keys`; `NormRef` пятиполевой, без пустых `document`.
- Тесты: `88 passed` (корпусные проверки по всем 5 СП выполняются, не скипаются).
- Визуальная сверка PDF ↔ БД подтверждена для пилота (формула 5.7, таблица 5.5) и СП 31
  (формула 9); HTML-генератор — `research.make_review_html`.

## 4. Над чем ещё стоит поработать

1. **LaTeX для формул без manifest.** Сейчас `latex`/`expression` заполняются только для
   человеко-проверенных формул `formulas.toml` (verified/human-verified). Остальные —
   `machine-extracted`, `latex` пуст. Нужен OCR-шаг (DocLayout-YOLO + pix2text) как отдельный
   этап с явным статусом; повышение статуса — за `norm-source-traceability` (WP3).
2. **Заголовки таблиц (WP9, задача 2.4).** Значения таблицы хранятся, но привязка «строка →
   символ+единица» и выбор строки по заголовку — отдельная задача каталога.
3. **Коэффициенты: edition/clause.** Для табличных коэффициентов `edition` сейчас
   `unverified` (инвариант допускает: `status=unverified`). После сверки с первоисточником
   (WP9, 2.5) edition/clause должны стать конкретными.
4. **Таблицы с одним номером на одной странице.** БД не хранит идентификатор pdf-таблицы;
   при нескольких таблицах с одинаковым номером на странице независимая сверка неоднозначна
   (roundtrip при этом точен). Решение — хранить `table_index`/bbox.
5. **Кириллические индексы в формулах — найден детерминированный путь (2026-10-04).**
   pix2text путает кириллицу (`h_зар` → `h_3arrom`), но текстовый слой PDF хранит её корректно.
   `research/text_layer_latex.py` собирает LaTeX из геометрии pdfplumber (size/top → индексы),
   NFKC для математических начертаний и таблицы Symbol-шрифта для PUA (`∑`, `≥`, `⋅`), а
   кириллицу транслитерирует в латиницу только для sympy. На СП 31 — **9/13 (69%)** против
   48% у pix2text, парсятся все формулы с кириллическими индексами. Это делает pix2text нужным
   только для сканов. Для продакшена: расширить `[parser.pua_map]` до полной таблицы Symbol и
   включить шаг как детерминированный OCR-free путь (вариант A2 в `RECOMMENDATION.md`).
   Варианты B (гибридный OCR) и C (fine-tune) остаются для сканов/сложной вёрстки.
6. **Коллектор зависит от сети** (`api.faufcc.ru`). Офлайн-цикл работает на уже скачанных PDF;
   стоит добавить проверку целостности/версий в коллекторе.
7. **Дедупликация формул.** На СП 22 из 133 детекций в БД 130 — нужно явно логировать, какие
   три отброшены (сейчас молча).
8. **Покрытие кода.** Целевое ≥ 95% branch coverage держать при добавлении модулей; проверять
   `pytest` с `DEC_DATABASE_URL` (иначе DB-тесты скипаются).
9. **Коллизии `id` кириллица↔латиница — исправлено (2026-10-04).** `cyr_map` транслитерировал
   кириллицу в латиницу (а→a, с→s, е→e, р→r, у→u, к→k, А→a), из-за чего омографичные кириллица
   и латиница получали один `id` (в БД 11 групп: `a`, `s`, `e`, `k`, `r`, `u_i`, …). Решение в
   `parser/symbols.py`: обозначению с кириллицей добавляется суффикс `_cyr` и сохраняется регистр
   (`А`→`A_cyr`, `а`→`a_cyr`, `\text{с}`→`s_cyr`; латинское `s`→`s`). Кириллических коллизий — 0
   (проверено на 5 СП: было 8 групп по извлечению / 11 с manifest, стало 0; тесты
   `tests/test_symbols.py`, `tests/test_cyrillic.py`, эксперимент в `nb05`). Аудит и миграция
   старых данных — `python -m normatives_pipeline.parser.cyrillic [--apply]`.
   Остаётся: форматные коллизии `_g` vs `_{g}` между manifest `formulas.toml` и извлечением —
   отдельная задача нормализации LaTeX (не про алфавит).
