# Verifier's check sheets

This folder holds the check sheets of the verifier of interim normative data
(`interim-normatives-source`, design decisions 3, 10 and 11; tasks 7.3a-7.4 and 7.5). Git
tracks it, unlike the rest of `docs/` except `docs/decisions/` (Akim, 2026-10-27).

## Layout

- `<change>/<portion>.yaml` is the sheet the verifier fills in, signs and commits, for
  example `interim-normatives-source/P1-1.yaml`.
- `<change>/<portion>.md` is the readable view of the same sheet, generated with it.

## Rules

- Sheets are generated by `tools/digitization` (`python -m extractcmp build`) with every
  verdict empty. Only a verifier named in the manifest's `verifiers` decides `verdict`, `by`,
  `at`, `corrected` and `comment`. An agent may type them into a sheet only as the verifier
  dictates, item by item, and never chooses a verdict itself (Akim, 2026-10-27).
- The verifier signs a filled sheet with `python -m extractcmp sign <sheet> --by <name> --at
  YYYY-MM-DD` and commits it under their own git name, naming the portion in the commit
  message. Any edit after the signature voids it.
- `python -m extractcmp promote` accepts only a signed sheet whose last commit is by the
  signer and which has no uncommitted changes; it never writes in place.
- Sheets are documents: they are committed directly to `develop` (`AGENTS.md`, section 2).
- `detect-secrets` does not scan `docs/verification/**.yaml` (`.pre-commit-config.yaml`): every
  sheet carries SHA-256 digests in hex, which the hook reports as high-entropy strings. The
  Markdown views and this file are still scanned.
