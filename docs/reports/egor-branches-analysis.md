## Кратко

1. **Кандидат в первый тип расчёта уже подготовлен у Егора.** Это расчётное сопротивление грунта основания R (СП 22.13330.2016, формула 5.7, п. 5.6.7). Формула вручную занесена в реестр `formulas.toml` с выражением, LaTeX и обозначениями. Сам СП загружен в Postgres.
2. **Реестр формул — это позиция Егора по открытому вопросу «формулы в YAML или в коде»** (задача 7.2 WP2, Е9). По его журналу автоматическое извлечение формул (OCR) для MVP ненадёжно. Поэтому формулы один раз вносятся вручную в TOML, а пайплайн их доставляет. Чья это зона и как реестр связан со слоем параметров WP5, не решено.
3. **Хранилище Егора расходится с твоими спеками WP5.** У него одна БД `dec`, в WP5 их две. В схеме нет ревизий, нет хранения таблиц коэффициентов, нет `provenance` и `status`. Для R нужны коэффициенты из таблицы 5.5, а таблицы не сохраняются.
4. **Тулинг.** В корне репозитория уже есть `pyproject.toml` (pytest с покрытием ветвей), `tests/` и `docker-compose.yml`. Егор использует `mypy`. Это надо учесть в change WP6.
5. **Поиск по нормам.** Решено делать лексический поиск с лемматизацией и заменой ё→е. Эмбеддинги — позже, как гибридный слой.
6. **Всё это не в `develop`**, включая два документа, адресованных тебе.

## 1. Полезное для текущей работы

### 1.1 Реестр формул `formulas.toml` и первый тип расчёта

В реестре две формулы СП 22.13330.2016:

| Формула | Пункт | Что считает | Входы |
|---|---|---|---|
| 5.1 | 5.3.16 | расчётное значение характеристики грунта X | нормативное значение и коэффициент надёжности по грунту |
| 5.7 | 5.6.7 | расчётное сопротивление грунта основания R, кПа | 12 величин: коэффициенты условий работы, коэффициенты M_γ, M_q, M_c по таблице 5.5, ширина подошвы, глубины заложения и подвала, удельные веса грунта, сцепление |

**Что это даёт для первого типа.** R — классический расчёт фундаментов мелкого заложения, и у Егора по нему уже есть всё, кроме данных таблиц. Предложить R первым типом стоит, если в методическом пособии есть не меньше трёх разобранных примеров его вычисления (раздел 1 `reference-examples-foundations.md`).

**Чего не хватает:**
- Коэффициенты M_γ, M_q, M_c берутся из таблицы 5.5. Таблицы Егор пока не сохраняет (см. 2.2).
- У части безразмерных величин единица пустая. Это нормально, но в движке каждая величина должна явно помечаться как безразмерная (требование WP2 о единицах).

**Контрольный пример в тестах Егора — не эталон.** Тест `test_formula_code.py` получает R = 143,75 кПа на произвольных числах. Для проверки связки «выражение → исполняемый код» он годится, но как эталонный пример WP4 — нет: у значений нет источника.

### 1.2 Как формула становится кодом (журнал, записи 13, 20, 21)

- Разбор LaTeX (`parse_latex`) молча портит русскую нотацию: `γ_{c1}` превращается в `c·1`, `γ_{II}` — в `I·I`.
- Текстовый слой PDF для формул непригоден: греческие буквы идут PUA-глифами, порядок символов нарушен.
- Надёжный путь — явная таблица символов и выражение, построенное детерминированно, затем `sympy.lambdify`.

**Риск для WP2.** Если движок будет превращать строку `expression` из данных в функцию через SymPy, то `parse_expr` и `sympify` внутри используют `eval`, а `lambdify` генерирует код. Выражение из данных станет исполняемым кодом. При проектировании надо заложить безопасный разбор: белый список символов и операций или разбор AST. Кроме того, выражение должно проходить через фильтр `provenance`. Егор в своём дизайне явно пишет, что пайплайн выражения не исполняет, так что исполнять их будет твоя сторона.

### 1.3 Postgres и инструкция для тебя

- **Документы для тебя.** `docs/decisions/normatives-pilot-usage-akim*.md` описывает, как загрузить пилотный СП и запросить формулу (`python -m normatives_pipeline.search --json "..."`). `docs/decisions/normatives-postgres-storage*.md` описывает подключение и схему.
- **Подключение:** `postgresql://dec:dec@localhost:5433/dec`, контейнер `dec-postgres` (Postgres 14). Код берёт адрес из `DEC_DATABASE_URL`, а если переменная не задана, молча использует этот локальный адрес.
- **Схема:** `document`, `clause`, `formula`, `notation_entry`, `cross_ref`, все связаны через `document_id`. Уже загружено: СП 22.13330.2016 — 647 пунктов, 124 формулы, 141 запись обозначений, 56 ссылок на ГОСТ.
- **Расхождение в документации.** В документе о хранилище сказано, что compose-файла в репозитории нет. Но в той же ветке `docker-compose.yml` в корне уже есть.

### 1.4 Поиск по нормам (записи 14, 16–18)

- Для MVP выбран лексический поиск. Эмбеддинги (`multilingual-e5-small`) не обошли TF-IDF, поэтому они позже, как гибридный слой.
- **Обязательные правила для любого поиска в продукте:** нижний регистр, ё→е в запросе и в документе, лемматизация (`pymorphy3`), очистка символов замены.
- Поиск идёт только по заранее собранному индексу, PDF при запросе не читается.

Для каталога норм и поиска во frontend это готовые требования.

Мелкое расхождение. В записи 14 для MVP назван `pg_trgm`, и WP5 тоже планирует GIN + `pg_trgm`. Но в коде Егора сейчас `to_tsvector('simple', …)`.

### 1.5 Формулы без номеров (запись 19)

В СП 45.13330.2017 многие формулы не пронумерованы (пример из журнала — п. 13.8). Егор предлагает находить формулу по структуре, а в качестве номера брать номер пункта или синтетический номер.

Для `NormRef` это важно. Локатор формулы в грамматике Егора (`форм. (N)`) здесь неприменим, а синтетический номер нельзя выдавать за номер из документа: правило «не выдумывать пункт». Нужно договориться, как такой локатор записывается и помечается.

### 1.6 Тулинг (для change WP6)

- **`pyproject.toml` в корне** содержит только `pytest` (`testpaths = ["tests"]`) и `coverage` с покрытием ветвей. Покрытие считается по `normatives_pipeline`.
- **Тесты Егора лежат в `tests/` в корне.** Корпусные тесты пропускаются, если в `norm-docs/` нет PDF.
- **Проверщик типов.** Егор пишет под `mypy`: в коде стоят `type: ignore[import-untyped]`, а в задаче 5.2 контракта формул сказано «`ruff` + `mypy` clean». Если выбрать `ty`, у двух зон будут разные проверщики. Это довод в пользу `mypy` при выборе в WP6.
- **Раскладка.** Надо решить, будет ли корневой `pyproject.toml` общим для двух пакетов, или у backend будет свой `backend/pyproject.toml`. То же для `tests/`.
