### Принятая форма NormRef

```
NormRef {
  document:   string                       # обозначение как в документе; всегда конкретное
  edition:    string | unverified
  clause:     string | unverified          # один локатор: пункт, таблица или формула
  status:     verified | unverified
  provenance: human-verified | machine-extracted
}
Инвариант: status = verified => edition и clause конкретные.
EngineerRule {engineer, rationale}
Step.norm_refs: NormRef[]                  # не меньше одной
Source = NormRef[] (не меньше одной) | EngineerRule
```

- `status` — только проверка; статус документа (in force, superseded, withdrawn) в NormRef не входит и берётся из каталога по `(document, edition)`.
- `EngineerRule` допустим только для правила округления и источника validated range; в конверт добавлено поле `engineer_rules`. Это следствие решения 3, в вопроснике Егору оно отдельно не обсуждалось.
- Сохранённая ссылка неизменяема; `document` — строка-обозначение; формат `edition` определяет Egor.

### Метрики

- **Отклонение от эталонов:** по каждой величине, в её единице, рядом с её допуском; общего процента нет.
- **Воспроизводимость:** доля эталонов, у которых два прогона дают идентичные конверты без `result_id`; ниже 100% — NO-GO.
- **Полнота трассируемости:** доля шагов, у которых все `NormRef` проверены, среди шагов неотказанных конвертов. Правила инженера считаются отдельным счётчиком. Порога нет, вердикт метрика сама не решает, но без неё GO недействителен.

## Решения по ходу работы

1. **Замена вместо переименования.** Валидатор требует сохранить у MODIFIED старый сценарий «Fast and accurate», который склеивает обе цели. Поэтому «Non-functional — performance and accuracy» оформлено как REMOVED (с Reason и Migration) и ADDED «Calculation accuracy» плюс «Calculation latency».
2. **`result_id` не основа сравнения.** Контракт исключает его; основа — `input_hash`, `engine_version` и содержимое конверта.
3. **Ключ корпуса.** В конверте нет поля редакции, поэтому `input_hash` (охватывает идентичность набора параметров) заменяет её в ключе записи.
4. **Редакция нормы в примере.** Методичка может считать по другой редакции, чем движок. Поле `source_norm_edition` (допустимо `unverified`) делает несовпадение видимым; ни одна редакция не названа.
5. **Допуск.** Спека задаёт только поля и правило сравнения (абсолютный или относительный, симметричный). Числового допуска нет.
6. **Новое требование в `development-process`.** Существующие требования не переписаны, потому что файл общий и соседнее требование меняет `team-roles-update`. Гейт применяется только к change с кодом, который добавляет или меняет расчёт.
7. **Заполнение эталонов** вынесено из change в раздел «следом»: по одной задаче на тип расчёта, после применения change.
8. **Структура предупреждений** (по итогам ревью core-contract): предупреждение записывает входное значение, validated range и его `Source`.
