## Блокеры

1. **Спек-делта противоречит собственному, уже принятому решению 3 design.md и
   задачам 5.1-5.2.** `specs/backend-architecture/spec.md:39-56` (сценарий «No
   hardcoding», требование «Parameters stored in YAML») всё ещё говорит, что
   нормативные коэффициенты/формулы читаются «из конфигурации или файла параметров» /
   хранятся в `.yaml`. `design.md:47-56` (решение 3, закрыто 2026-09-27, закрывает
   задачу 9.5) и задачи 5.1-5.2 `tasks.md` говорят обратное: формулы/коэффициенты из
   нормы идут из `dec_normatives` через provenance-гейт слоя параметров; `.yaml` — только
   для инженерных значений. Спек-делта не была синхронизирована с пересмотренным
   решением. Закрывается правкой двух затронутых сценариев/требований в
   `specs/backend-architecture/spec.md`.

2. **Задача 6.2 / решение 7 design.md противоречат требованию «чистая функция
   расчёта» `calculation-core-contract`.** Задача 6.2 tasks.md («reference
   implementation reading parameters from the parameters layer») подразумевает I/O
   внутри движка; `calculation-engine/spec.md` (в `calculation-core-contract`) требует,
   чтобы каждый тип расчёта был чистой функцией без чтения внешнего состояния.
   `calculation-core-contract/design.md:209-215` уже называет этот конфликт и держит
   (пока открытую) sync-задачу — свою задачу 7.2 — для переформулировки 6.2 и решения
   7. Синхронизация не сделана.

3. **Задача 5.1 зависит от нераскрытой межкомандной/межчейнджевой зависимости.**
   `design.md:55-56` (конец решения 3): задачи 5.1-5.2 читают из `dec_normatives`
   «once that reading path exists». Этот путь зависит от открытой задачи 9.3 (место
   кода нормативов, ждёт Егора) и от собственной открытой задачи 7.2
   `calculation-core-contract` (provenance-гейту нужно состояние верификации из
   пайплайна, которого пока нет, `calculation-core-contract/design.md:271-276`).
   Задача 5.1 находится в разделе 5 (заявлен как готовый, без зависимости от Егора),
   но не может быть выполнена в текущем объёме до решения 9.3 и 7.2
   `calculation-core-contract`. Заголовок `tasks.md` (добавлен 2026-09-28) эту
   зависимость не раскрывал.

4. **В `tasks.md` нет ни чек-листа DOR, ни раздела DOD/Go-No-Go.**
   `openspec/config.yaml` (`rules.tasks`) требует оба; `AGENTS.md`, разделы 3-4,
   требуют то же на уровне change. **Закрыто этой сессией правкой `tasks.md`,
   2026-09-28** (добавленные разделы DOR-чеклиста и DOD/Go-No-Go фиксируют именно
   текущий статус NOT READY, а не заявляют готовность).

5. **Задачи 5.2 и 6.2 называют домен-плейсхолдер внутри неотложенных разделов.**
   Задача 5.2 tasks.md (`params/normatives/beam_deflection.yaml`) и 6.2
   (`engine/beam_deflection.py`), плюс решение 7 design.md. `retarget-mvp-domain`
   активен и уже вводит `foundations-shallow`; `calculation-core-contract` уже ждёт
