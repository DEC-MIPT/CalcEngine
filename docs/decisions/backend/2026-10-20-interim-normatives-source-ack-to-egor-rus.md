## Что делает change

`openspec/changes/interim-normatives-source/` (коммит `2b56550`, запись о готовности
`2026-10-20-interim-normatives-source-readiness-rus.md`) добавляет:

- второй, временный источник параметров `InterimParameterSource`. Он читает YAML-файлы из
  `backend/interim_normatives/<документ>/`. Этот каталог в зоне бэкенда, не в `params/`,
  `ml/` или `infra/`;
- настройку `DEC_PARAMETER_SOURCE=catalog|interim`. По умолчанию остаётся `catalog`, и
  настройка переключает сразу все типы расчёта. Поиск и документы нормативов при любой
  настройке читают твой каталог;
- запись верификации рядом с каждым значением. Профиль `strict` берёт только значения,
  проверенные верификатором; `draft` берёт все и помечает результат;
- необязательный объект `parameter_source` в конверте результата (вид, SHA-256 данных,
  профиль). Он показывается на экране результата и в отчёте;
- дату и событие отключения в данных. Событие — это CH3: сверить временные данные с
  каталогом, переключиться обратно и удалить данные.

## Что прошу подтвердить

1. **Change целиком**, как второй разработчик. `openspec/` общий, а change добавляет одну
   capability (`interim-normatives`) и три ADDED-требования рядом с `calculation-api`,
   `report-generator` и `transparent-output`.
2. **Исключение из правила «нормы только из каталога»** (`specs/interim-normatives/spec.md`,
   требование «Scoped exception to the normative-database rule»; `design.md`, решение 9).
   Оно ограничивает четыре требования, одно из них — в твоём контракте WP9:
   `normative-catalog-backend` «Catalog parameter source».
   - Исключение действует только при `DEC_PARAMETER_SOURCE=interim`, только для файлов
     временного каталога и только до события отключения.
   - При настройке по умолчанию для каталога ничего не меняется.
   - Четыре MODIFIED-дельты добавятся после архивации этих change (задача 1.4).
3. **Статус `NormRef` не поднимается.**
   - Значение, проверенное верификатором, всё равно доходит до результата как `unverified` /
     `machine-extracted`.
   - Отметка верификатора — только гейт профиля `strict` (`design.md`, решение 4).
   - Так сохраняется твоё правило: бэкенд никогда не поднимает статус. Что отметка значит для
     статуса ссылки, решит WP3.

## Answers

1. **Подтверждаю.** Change целиком.

2. **Подтверждаю.** Исключение из правила «нормы только из каталога» — в рамках
   заявленных ограничений (только при `DEC_PARAMETER_SOURCE=interim`, только для файлов
   временного каталога, только до события отключения).

3. **Подтверждаю.** Статус `NormRef` промежуточным источником не поднимается.
   Существующее правило бэкенда остаётся в силе.

4a. **Да.** Пять групп представлений `catalog_read` возвращают строки, поля которых
    совпадают с перечисленными в таблице один к одному. Имена параметров, символы и
    единицы — одинаковые ключи в обоих источниках, поэтому CH3 может сравнивать запись
    за записью без переименований. Изменений в представлениях до CH3 для пилотного
    объёма нет.

4b. **Да.** Pipeline строит деревья с этими видами узлов: `number`, `symbol`, `add`,
    `sub`, `mul`, `div`, `pow`, `neg`, `call`. Список функций: `sqrt`, `exp`, `ln`,
    `log10`, `sin`, `cos`, `tan`, `abs`, `min`, `max`. Это формат, зафиксированный в
    WP9 (`normative-catalog-backend`, решение 3). Формат не менялся.
