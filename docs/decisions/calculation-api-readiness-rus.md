Major первого прохода и как они закрыты:

1. Сервер не запускался без `DEC_APP_DATABASE_URL`, потому что корень параметров лежал
   в `Settings`. Закрыто: `DEC_PARAMS_ROOT` перенесён в `ApiSettings`, где нет
   обязательных полей; `Settings` читается лениво; если база не настроена или
   недоступна, ответ — `503 database_unavailable` (решение 7 дизайна, задача 3.3).
2. В таблице статусов не было `413`, неизвестного маршрута и неверного метода. Закрыто:
   требование «Error responses» содержит полную таблицу (404, 405, 409, 413, 422, 503,
   500) со сценариями.
3. У формулировки «ответ называет вход» не было формы. Закрыто: каждый ответ `422`
   содержит `fields`; у `invalid_input` место ошибки — `["body", "inputs", "<имя
   входа>"]`, по одной записи на вход.
4. Отчёт по результату, тип которого больше не зарегистрирован, давал `404` только в
   дизайне. Закрыто: `409 calculation_type_not_registered` есть в спеке, в дизайне и в
   задачах 4.4 и 5.4.
5. Задачи 2.3, 4.2 и 5.2 не укладывались в одну сессию. Закрыто: разделены на 2.3-2.5,
   3.3, 4.2-4.4 и 5.2-5.5.
6. Пункт DOR «Зависимости выполнены» был открыт без обоснования. Закрыто: используемые
   задачи WP2 названы, и все они реализованы на исходной ветке; задача WP2 6.2 (задача
   Егора 1.8) влияет только на порядок слияния.

Minor 7-13 первого прохода исправлены в том же круге: формулировка повторного прогона,
измеримая задержка, связь с требованиями `web-platform`, `405` на методы изменения,
проверки лога для `422` и `503`, открытые вопросы, происхождение «Applicability check
with three outcomes» из WP2. Minor второго прохода исправлены после него: код ответа на
неизвестную единицу, ошибка с указанием значения в задаче 4.1,
`GET /calculation-types` без URL базы в задаче 5.1.

## Поправка: единицы каждого входа в списке типов (2026-10-03)

Перед задачей 5.3 проверка клиентской стороны показала, что у формы ввода (`web-platform`
«Calculation input form», изменённое в дельте WP1: поля из контракта типа, без зашитых
полей) нет задачи ни в одном change, а `GET /calculation-types` не давал форме списка
допустимых единиц, и форме понадобилась бы своя копия словаря единиц. Решение Акима:
перечислять у каждого входа единицы словаря его размерности. Изменены: требование
«Calculation types listing» и новый сценарий «Units a form can offer»; решение 10
`design.md`; задача 5.2a (после 5.2) и строка покрытия; проверка задачи 2.2; один пункт
proposal. Сама форма остаётся вне этого change.
