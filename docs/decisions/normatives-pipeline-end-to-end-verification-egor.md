# Сквозная проверка пайплайна нормативов — Egor, 2026-10-04

Ветка: `feature/normative-formula-contract/data` (зона data/ml).
База для чистого прогона: пустая `dec_e2e` (`postgresql://dec:dec@localhost:5433/dec_e2e`).

## Что сделано

Проверен полный цикл на **всех текстовых СП** в `docs/normative-base/`:
получить PDF → извлечь текст/таблицы/формулы → занести в БД → прочитать то, что отдаём
потребителю (Акиму) → сверить с содержимым PDF. Рабочий код пайплайна не менялся.

Инструменты (только библиотеки, без LLM):
- `ml/research/verify_end_to_end.py` — автоматическая сквозная проверка (PASS/FAIL);
- `ml/research/make_review_html.py` — HTML для визуальной сверки PDF ↔ БД.

- `ml/tests/test_extractors_corpus.py`, `ml/tests/test_ingest.py`: путь к PDF считался как
  `parents[1]` (= `ml/docs/...`) вместо корня репозитория. Из-за этого 13 корпусных/интеграционных
  тестов **всегда скипались**. Исправлено на `parents[2]`; тесты проходят на реальных PDF.

  добавляется суффикс `_cyr` с сохранением регистра (`А`→`A_cyr`, `а`→`a_cyr`, `s`→`s`).
  Было 8 групп коллизий по извлечению (11 с manifest), стало 0. Добавлены
  `parser/cyrillic.py` (аудит/миграция, `--apply`), тесты `tests/test_cyrillic.py`, расширен
  `research/nb05_final_pipeline.ipynb` (раздел 4, реальные замеры). Тесты: `106 passed`;
  `ruff` и `mypy` чисто.
