## Вопросы

### 1. Как выбирается первый тип? (Егор и PM)

- **Предложение.** Первый тип — тот, который (а) пособие разбирает не меньше чем в трёх
  примерах, чтобы у WP4 были 3 эталона; (б) опирается на нормы, по которым пайплайн Егора
  может дать пилотные данные (вопрос 3); (в) PM принимает как часть объёма MVP.
- **Почему.** Без (а) набор эталонов недействителен (сценарий WP4 «Too few or incomplete
  examples»); без (б) у первого среза нет нормативных данных; (в) — решение PM об объёме.
- **Ваша сторона.** Согласны, или измените правило.

**Ответ (Егор).** Согласен с правилом: первый тип покрыт минимум 3 решёнными примерами в методичке, опирается на документы, которые пайплайн может отдать пилотом, и принят PM.

**Ответ (PM).**

### 2. Какой тип? (Егор и PM)

- **Предложение.** Аким читает пособие и предлагает тип (или типы) в разделе 1
  `reference-examples-foundations.md`, с числом разобранных примеров и страницами.
  Предлагаемый тип: `<ожидается: Аким заполняет по пособию>`.
- **Предварительный кандидат.** Расчётное сопротивление грунта основания R, формула 5.7,
  п. 5.6.7 СП 22.13330.2016 (номера из `formulas.toml` Егора, `unverified`). Формула уже
  есть в реестре Егора, СП загружен. Кандидат станет предложением, только если в пособии
  не меньше трёх разобранных примеров; ему нужен также ответ на вопрос 3 (таблица
  коэффициентов).
- **Ваша сторона.** Подтвердите или отклоните предложенный тип. После подтверждения Егор
  вписывает его в «In-scope calculation types» `foundations-shallow` (задача 3.1).

**Ответ (Егор).** Подтверждаю R (форм. 5.7, п. 5.6.7, СП 22.13330.2016) кандидатом: он уже в реестре (`formulas.toml`) и СП загружен. Зависимость — таблица коэффициентов 5.5 (см. ревью контракта, вопрос 7).

**Ответ (PM).**

### 3. Пилотные нормативные данные для этого типа (Егор)

- **Что есть сейчас** (по твоим записям; редакции `unverified`, пока не сверены с
  первоисточником):
  - Пилотный СП парсера: СП 22.13330.2016 «Основания зданий и сооружений», пилот по
    мелкому заложению; уже загружен в Postgres (647 пунктов, 124 формулы, 141 запись
    обозначений; `docs/decisions/normatives-postgres-storage.md` в
    `feature/normative-parser/ml`).
  - Скачанный корпус (`ml-model-journal-rus.md`, запись 4, только действующие редакции):
    СП 22.13330.2016, СП 24.13330.2021, СП 45.13330.2017 (фундаменты), СП 30.13330.2020,
    СП 31.13330.2021 (вода); у СП 32.13330.2018 нет файла в реестре. В твоей заметке для
    Акима упомянут ещё скан СНиП без названия.
  - Задача 1.2 `normatives-collector` (список пилота из 5 документов) ещё открыта.
- **Вопрос.** Опирается ли выбранный тип только на СП 22.13330.2016 или ему нужен ещё
  документ (например, СП 24 или СП 45)? Если нужен, когда он будет загружен? Список пилота
  из 5 документов в задаче 1.2 — это пять скачанных документов выше? Если тип — R: его
  коэффициенты `M_γ`, `M_q`, `M_c` берутся из таблицы 5.5, а таблицы пока не сохраняются.
  Когда эта таблица будет доступна, каждое значение со своим `NormRef` (см.
  `normatives-formula-contract-review-egor-rus.md`, вопрос 7)?
- **Твоя сторона.** Назови документы и редакции, которые пайплайн даст для этого типа,
  с пометкой `unverified`, пока они не сверены с первоисточником.

**Ответ (Егор).** R опирается только на СП 22.13330.2016. 5-document pilot list (задача 1.2) = пять скачанных (СП 22.13330.2016, СП 24.13330.2021, СП 45.13330.2017, СП 30.13330.2020, СП 31.13330.2021; у СП 32.13330.2018 нет файла в реестре). Таблица 5.5 (M_γ, M_q, M_c) сохраняется с этой итерации, каждое значение со своим `NormRef`, `unverified` до сверки.
